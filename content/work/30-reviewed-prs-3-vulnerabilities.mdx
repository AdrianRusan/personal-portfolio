**Short answer:** In March 2026 Claude Code agents opened 31 pull requests on my own admin dashboard in under three days, and I reviewed and merged 30. The repo had no tests and no CI, so my review was the only gate. It caught 3 shell-injection paths from request input, a path traversal and a deleted allowlist before merge. On 12 October 2026 I re-audited the run and found 5 security bugs my review let through: 3 shell commands built from strings, one of them from request input, and 2 stored XSS sinks. All 5 are still open in that repo.

The repo is my own agent-monitoring dashboard: no client code, no client data. Every number on this page comes from its git history and `gh pr view`, and the commit SHAs are listed so the claims can be checked against the repo.

## The setup

- **Repo:** a Next.js admin dashboard with a SQLite database and API routes that call CLIs (`gh`, `rg`, `du`, a cron tool).
- **Work:** 33 scoped issues for version 2.0, one Claude Code agent and one git worktree per issue, every agent reading the same `CLAUDE.md`.
- **Gate:** no test suite, no `test` script, no `.github/` directory. Nothing merged until I had read the diff and pushed fixes for what I found.
- **Models:** the commit trailers name Claude Sonnet 4 and Claude Opus 4.6. Of the 7 commits behind the security findings below, 4 carry a Sonnet 4 trailer and 3 carry none.

## What review caught before merge

| PR | What the agent wrote | Where the input came from | Fix |
| --- | --- | --- | --- |
| #112 | A job ID from the URL path inside an `execSync` string. The rewrite also deleted the allowlist that an earlier security fix had put on that ID. | request (URL) | `237cfaa` → `10bf07e` |
| #111 | A log-search query inside a shell string, behind the agent's own character filter | request (query) | `cf68b1a` → `42f1b03` |
| #121 | A memory-search query, the same pattern as #111 | request (query) | `d718495` → `b2d68a2` |
| #119 | A file path built from a route parameter with no containment (path traversal on read and write) | request (route) | `199d72c` → `e62ef29` |
| #113 | A config path from an environment variable inside a shell string | operator config | `affddfd` → `b290d1c` |

Only #112 was directly exploitable as written. #111 and #121 sat behind a regex that stripped every shell metacharacter, so they were one careless edit away from open. The code for all three is in [The Shell-Injection Bugs My Agents Wrote](/blog/catching-shell-injection-agents-wrote).

## What review missed

| PR | What got through | How it was found |
| --- | --- | --- |
| #98 | `repo`, `state` and `label` from the URL query string go into a `gh` shell command (`app/api/github/issues/route.ts`) | an agent classifying the fix commits on 12 Oct; I confirmed it in the code |
| #109 | A PR number and a repo name read from the database go into an `exec` shell string | a fact-check of the run on 11 Oct; the AI reviewers flagged it too |
| #117 | A stored repo name, editable in the UI, goes into `sh -c`. Review added a format check, and #118 deleted its only call when it merged 3 minutes later. | the same fix-commit audit, 12 Oct |
| #111 | Log lines rendered as HTML (`dangerouslySetInnerHTML`) with only the search term escaped: stored XSS | AI reviewers on the original commit, 12 Oct |
| #121 | Memory-file lines rendered the same way: stored XSS | AI reviewers on the original commit, 12 Oct |

All 5 are open: present at the repo's last commit, `30a6992` on 13 March 2026. The dashboard hasn't been touched since.

The same audit found one functional bug review missed: the #109 diff tab reads `commit.sha`, but `gh` returns `oid`, so the tab throws on any PR with commits.

## Why these got through

**#98: the fix commit touched the vulnerable line and kept it.** Review asked for a cleanup, and the fix commit (`28f057d`) moved the route's private `gh` wrapper into a shared helper and typed it. The string that carries `repo` into the shell came along unchanged. A review comment on a line got read as a review of the line.

**#117: a check added in one PR was deleted by the next.** #117 and #118 were open at the same time. The format check I asked for landed at 07:25 UTC on 13 March, and #118's feature commit removed its only call at 07:29. Each PR was fine against its own base. Nobody, me included, reviewed the merge of the two.

**#111 and #121: the fix already existed in the repo.** On 16 February a security fix (`32fc549`) added `sanitizeSnippet` to the global search results for exactly this pattern. In March two agents wrote two new search screens with their own highlight helpers and skipped it. My review fixed the shell call in both PRs and never looked at how the results rendered.

**#109: I trusted the database.** The values came from rows my overnight worker writes, so I ranked them below request input and let the call through. Anything that can write that row can run a command.

## The rest of review

25 of 30 PRs needed fixes. Their fix commits hold 64 fixes for 61 distinct defects, because 3 defects were fixed twice on parallel branches. 12 fixes were security fixes. The largest groups were re-implemented helpers (11) and type-safety fixes (10). By my reading of the code, 9 of the 61 defects would have broken the build or a page at runtime; nothing was run to confirm it. The breakdown by category is in [How to Review AI-Generated Code](/blog/what-agents-get-wrong).

## What I'd run now

The check that catches all 5 misses is mechanical: flag every shell string with a variable in it and every raw-HTML sink, wherever the value comes from, then trace each hit.

```bash
git diff origin/main...HEAD -U0 | grep '^+' \
  | grep -iE "exec[a-z]*\(|shell: true|dangerouslySetInnerHTML"
```

I ran it on the 5 agent commits behind the misses. It returns 4 or 5 lines per commit, and every miss is among them. It also returns safe calls, like `execFileSync` with an argument array, so tracing each hit is still the work. A CI step that fails on a new hit until someone signs it off is the second gate a repo like this needed.

I also ran two AI reviewers, Claude Code's `/code-review` and my own three-agent panel, on the 7 original agent commits behind the security findings. Both flagged the #109 shell string and both XSS sinks.

Generation was the cheap part of this run. Review set the pace, and review was also where the misses came from, which is why I now run a machine pass before I read a diff and still read every diff myself.
