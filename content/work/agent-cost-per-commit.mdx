My agent cost per merged PR fell from $73 to $32 between July and August, the month I cut the text loaded on every turn, though the drop started before the first cut. From September to the first days of October it went from $49 to $69, and the first version of this page compared those numbers across a counting change it shouldn't have.

**Short answer:** I track Claude Code cost per merged PR in a ledger that records tokens, commits and merged PRs per day. July to August, on one counting method, cost per merged PR fell 57% in the month I cut the text loaded on every turn. On the current method, September averaged $49 per merged PR and the first 11 days of October $69. Subagent turns doubled, headless runs jumped and the mix of work across my accounts shifted while merged PRs per day fell, and I haven't measured which of those drove it. The dollars are list-price replacement cost, not my invoice, and at the Opus 5.5 rates most sessions ran on they would be half to two thirds of that.

## How I count

1. **Source.** A private ledger reads my Claude Code transcripts every night and records, per day, tokens and their list-price cost, the commits in my repos and the PRs merged under my GitHub accounts. It covers all my Claude Code accounts. Figures here are totals, never per client.
2. **Price.** Every token is priced at Opus 5 list rates: $5 per million input, $25 output, $0.50 cache reads, $6.25–$10 cache writes. Most of my sessions ran on Opus 5.5, which lists at $4, $20 and $0.20 ([Anthropic pricing, fetched 12 Oct 2026](https://platform.claude.com/docs/en/about-claude/pricing)). With a quarter of my messages on Opus 5 and most of the rest on Opus 5.5, the same work comes to half to two thirds of the ledger's dollars, by my arithmetic. Moving work to a cheaper model doesn't show up in the ledger at all. Only fewer tokens do.
3. **Not an invoice.** These sessions ran on Claude subscriptions with a flat fee. The dollars measure compute used.
4. **Two methods.** Until September the ledger priced every transcript entry, which counts each API response about twice (2.04x on a 30-day re-scan). It also read only two of my four Claude Code accounts. From 11 September it counts each response once, across all accounts. July and August compare with each other, and September and October compare with each other. Never across.
5. **Per merged PR first.** A merged PR is tied to a GitHub account and someone reviewed it. Agent commits are fine-grained checkpoints, so cost per commit moves with commit habits as much as with cost.

I matched the weekly cost against the commit history of my Claude Code config.

**The first drop came before any change.** Subagent turns per prompt halved in the first week of August, and cost per PR fell with them. No config commit landed that week. My workflow changed, and no file records how, so I don't claim a cause.

**Less text injected into every turn (10 August).** A hook added a reminder to every message I sent, and nothing showed it saved anything, so I turned it off. The same change parked ten skills for stacks I wasn't using, because every installed skill adds its description to what each session loads.

**Shorter instructions (23 August).** An audit of my own setup cut `CLAUDE.md` and the rule files from 9,976 words to 4,106. Sessions load them at the start, and the model rereads them from the cache on every turn.

Full months, same method:

| | July | August | Change |
|---|---:|---:|---:|
| Cost per merged PR | $73.4 | $31.6 | −57% |
| Cost per commit | $35.2 | $11.4 | −68% |
| Merged PRs | 477 | 395 | −17% |
| Commits | 995 | 1,091 | +10% |
| Subagent turns | 144k | 43k | −70% |

Cost fell after both dated changes and stayed low. They line up with the drop. I can't show how much of it they caused, and one more thing moved: the mix of work across my accounts and clients shifted from month to month, which changes cost per PR on its own.

After the counting change, cost per merged PR rose every week but one: $52, $51, $56, $65. Comparing September with the first 11 days of October on the same method:

| Per active day | September (19 days) | 1–11 October (11 days) | Change |
|---|---:|---:|---:|
| List-price cost | $932 | $1,126 | +21% |
| Merged PRs | 19.1 | 16.3 | −15% |
| Commits | 80.7 | 47.0 | −42% |
| Subagent turns | 1,411 | 3,059 | +117% |
| Cost per merged PR | $49 | $69 | +42% |

Spend per day rose a fifth, and merged PRs per day fell. Subagent turns per day more than doubled. In the first ten days of October, 618 of my 770 Claude Code sessions were headless scripted runs, against 14 of 279 in September (counted from my session logs). The mix of work across my accounts also moved most in October. I haven't measured how much of the cost the headless runs or the mix account for, so the cause is open. The ledger did its job: it caught a 42% rise within a month, while the monthly total would have looked like a busy month.

## What I got wrong in the first version

The first version of this page said September was "roughly $23 on the old count, twice August" and that early October was "back above July". Both compared numbers across the counting change. The old method also read only two of my four accounts, so a 2x conversion can't bridge the gap, and I don't know the real ratio. The page also led with cost per commit, which my own ledger rates as the weaker metric. This version leads with merged PRs and compares only like with like.

## How much does Claude Code cost per developer?

Anthropic's docs put the enterprise average at about $13 per developer per active day and $150–250 per developer per month, with 90% of users under $30 per active day ([Claude Code docs, fetched 12 Oct 2026](https://code.claude.com/docs/en/costs)). Gartner, as reported in June 2026, found that nearly a quarter of tech leaders spend $200–500 per developer per month on AI coding tools and about 6% spend more than $2,000 ([DevOps.com, 30 Jun 2026](https://devops.com/ai-coding-costs-could-exceed-developer-salaries-gartner-warns/); Gartner's own release returned an error when I fetched it).

At Opus 5 list price my setup costs about $930 per active day, around 70 times Anthropic's average, or roughly 35 to 45 times at Opus 5.5 rates. I'm not a typical seat: up to 18 sessions at once, over a thousand subagents in 66 days, and orchestration runs that start other agents. That is why I run on flat subscriptions, and why the useful number for a buyer is the unit cost: about $49 per merged PR in September at Opus 5 list prices, $25–32 at Opus 5.5 rates.

## Why measure per merged PR, not per commit?

A commit from an agent is a checkpoint, and agents that commit every working step can double the commit count without doing more work. September had 1,533 commits and 362 merged PRs. A merged PR passed review and changed the product, so cost per merged PR moves only when the cost of shipping moves.

## What I'd check first on a team's setup

1. **Cost per merged PR, weekly, on one counting method.** A monthly total would have hidden a 42% rise in mine.
2. **What loads on every turn.** A hook that injects text into every message, unused skills and a long `CLAUDE.md` are paid for on every turn. My cut from 9,976 to 4,106 words lined up with the July–August drop.
3. **Headless runs and subagent turns, counted apart from interactive work.** In my October data subagent turns per day doubled and headless sessions went from 14 to 618, while merged PRs per day fell.

The measurement is what lasted. Without the ledger I would have reported "57% lower" in August and missed the climb in October.
